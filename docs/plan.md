# MyPaste 项目方案与规划（初版）

> 版本：v0.1 草案，2026-11-23
> 依据：[research.md](./research.md)
> 项目名 "MyPaste" 是暂定代号，正式开源前再定。

---

## 1. 产品定位

**一句话**：一款原生、轻量的开源剪贴板工具。用键盘就能完成所有操作；多台设备之间端到端加密直连同步，不需要任何服务器。

### 已确认的决策（2026-11-23）

| 项 | 决策 |
|---|---|
| 桌面 UI | **GPUI（gpui-kit 这条线）** |
| 首发平台 | **Windows**；然后规划移动端；macOS / Linux 放在之后 |
| 差异化 | ① **多设备同步（局域网优先，端到端加密）** ② **极致键盘流 + 粘贴队列** |
| 技术背景 | 熟悉 Rust 和前端 |

### 设计原则（做取舍时按这个优先级）

1. **快**：唤起、搜索、粘贴都要"感觉不到等待"。
2. **轻**：常驻时几乎不占资源。
3. **不丢数据、不泄露隐私**：本地优先；遵守系统隐私标记；同步全程加密。
4. **键盘优先，鼠标也友好**：所有操作都能用键盘完成。
5. **核心与 UI 分离**：核心是纯 Rust 库，桌面端、CLI、移动端都复用同一套核心。

### 不做什么（至少 v1 不做）

- 不做账号体系，不运营云服务。
- 不做 AI 功能（以后可以通过插件或 MCP 接入）。
- 不追求像 CopyQ 那样"什么都能配置"，默认值要好用。
- 不复刻 Paste 的视觉设计，走自己的设计语言。

### 3.1 Cargo workspace 结构

```
mypaste/
├─ crates/
│  ├─ mypaste-model      # ClipItem、Content、Op 等纯数据结构，不依赖平台
│  ├─ mypaste-store      # SQLite 迁移、仓储、blob 存储、清理策略
│  ├─ mypaste-search     # 查询语法解析、FTS5 / LIKE 召回、nucleo 排序
│  ├─ mypaste-pipeline   # 内容识别（链接/颜色/代码/邮箱…）、隐私过滤、转换器
│  ├─ mypaste-platform   # 平台 trait 定义 + 各平台实现（cfg 隔离）
│  ├─ mypaste-sync       # 设备身份、配对、操作日志、iroh 协议
│  ├─ mypaste-core       # 组装以上各层，对外提供 Service API 和事件流
│  └─ mypaste-ffi        # UniFFI 导出（移动端阶段再做）
├─ apps/
│  ├─ desktop            # GPUI 应用：窗口、托盘、热键、设置
│  └─ cli                # mypaste list/search/copy/paste-next …
├─ docs/
└─ xtask/                # 构建、打包、发布脚本
```

**约束**：`crates/` 下面的任何 crate 都**不允许依赖 GPUI**。这样即使以后 GPUI 出了问题，也只需要替换 `apps/desktop`。

### 3.2 进程与线程模型（桌面端）

单进程，内部分工如下：

- **UI 线程**：GPUI 主循环。
- **采集线程**：Win32 消息窗口 + `AddClipboardFormatListener`。收到变化后只读取原始数据，然后通过通道交给后台处理，**不在这个线程里做任何耗时操作**。
- **后台运行时**：tokio 跑在独立线程上，负责入库、生成缩略图、建索引和同步（iroh 需要 tokio）。GPUI 和 tokio 之间通过通道或事件通信。
- **数据库**：一个写连接（单写者），加一个只读连接池给 UI 查询用。

## 4. 数据模型（要点）

```text
ClipItem
  id            UUIDv7（按时间排序，跨设备唯一）
  hash          blake3(规范化后的主内容)，用于去重
  kind          text | link | image | files | rich(html/rtf) | color | code …
  primary       主内容（文本直接存；大于 256KB 的文本、所有图片都存到 blob）
  formats[]     原始的多种格式（HTML、RTF、PNG …），用于"带格式粘贴"
  preview       预览文本 / 缩略图路径
  source_app    来源应用（exe 路径、名称）
  device_id     来源设备
  created_at / last_used_at / use_count
  pinned / favorite / tags[] / note
  sensitive     是否命中敏感规则（只保留预览、不同步、可设置自动过期）
  deleted_at    墓碑（同步需要）
```

- **去重**：再次复制相同内容时不新建记录，只更新 `last_used_at` 并把它排到最前面。
- **清理策略**：可以按条数、天数、总容量限制；置顶和收藏的记录永远不会被清理。
- **元数据修改**（置顶、标签、删除）**一律写入操作日志 `Op`**。这是同步的基础，M1 就要做好，哪怕当时还没有同步功能。

## 5. 核心功能设计

### 5.1 极致键盘流（差异化之一）

| 操作 | 默认按键 | 说明 |
|---|---|---|
| 唤起 / 隐藏 | `Alt+V`（可修改） | 窗口出现在光标或鼠标附近，或屏幕中央（可设置） |
| 搜索 | 直接打字 | 唤起后焦点就在搜索框里 |
| 移动选择 | `↑↓` / `Ctrl+J/K` | |
| 粘贴 | `Enter` | 自动回到之前的窗口并粘贴 |
| 粘贴纯文本 | `Shift+Enter` | 去掉格式 |
| 快速粘贴第 N 条 | `Ctrl+1…9` | 列表上显示编号 |
| 预览 | `Space` / `Tab` | 大图、长文本、文件列表 |
| 置顶 / 收藏 / 删除 | `Ctrl+P` / `Ctrl+S` / `Del` | |
| 动作菜单 | `Ctrl+K` | 类似命令面板：转大写、JSON 格式化、去掉链接追踪参数、打开链接…… |
| 前缀过滤 | `img:` `link:` `app:chrome` `@today` `#标签` | 搜索语法，可以组合使用 |

**粘贴队列（差异化之一）**

1. 在列表里按 `Ctrl+Space` 多选，或者开启"录制模式"，把之后复制的内容依次加入队列。
2. 在任意应用里按**"粘贴下一个"热键**（默认 `Alt+Shift+V`）：把队列头部的内容写入剪贴板并模拟 `Ctrl+V`，然后队列前进一位。
3. 支持把多条合并成一条粘贴（可选分隔符：换行、逗号、Tab）。
4. **不用低级键盘钩子来拦截用户自己按的 `Ctrl+V`**，避免被杀毒软件误报、避免和其他软件冲突，只用独立的热键。

### 5.2 采集与隐私（Windows）

- 事件驱动采集；用剪贴板序列号去重；记录自己写入的内容哈希，避免把自己的写入又采集回来。
- **遵守系统隐私标记**：检测到 `ExcludeClipboardContentFromMonitorProcessing`，或者 `CanIncludeInClipboardHistory = 0` 时，**直接跳过**。
- 应用黑名单（内置常见密码管理器）、正则规则（私钥、token、身份证号等）、一键暂停记录。
- 敏感内容：可以设置"只保留 N 分钟"，并且永远不同步。

### 5.3 搜索

- 召回：FTS5 trigram（查询 ≥ 3 个字符）；1–2 个字符时对最近 N 条记录做 `LIKE` 查询。
- 排序：nucleo 模糊匹配分数 × 时间衰减 × 使用频率。
- 拼音首字母搜索：放到 M2 评估（对中文用户很有价值）。

### 5.4 美观

- 基于 gpui-kit 的主题系统，**自建一套设计规范**：间距、圆角、字号、动效时长都定成设计令牌。
- Win11 使用 Mica 背景，跟随系统的深色/浅色模式。
- 内容卡片按类型渲染：颜色显示色块，链接显示域名和网站图标，代码高亮显示，图片显示缩略图，文件显示图标和数量。
- 动效要克制：显示和隐藏 ≤ 120ms，不做花哨的转场。
- 布局：M1 只做一种"紧凑列表 + 右侧预览"的键盘友好布局，其他布局放到 M2 以后考虑。

### 5.5 多设备同步（差异化之一，M3）

| 层 | 方案 |
|---|---|
| 设备身份 | 每台设备一个 iroh Ed25519 密钥，`EndpointId` 就是设备地址 |
| 配对 | 局域网发现 → 显示 6 位配对码或二维码 → 双方确认 → 互相写入"受信任设备列表"。只有受信任的设备才能连接 |
| 传输 | iroh：同一局域网内直连；跨网络时可选择公共中继或**自建中继**（中继只转发密文） |
| 数据 | **每台设备一份只追加的操作日志**（新建、置顶、加标签、删除），每条带 HLC 时间戳。同步时双方交换版本向量，再补齐缺少的操作 |
| 冲突 | 新建条目用 UUID，天然不会冲突；元数据按字段"后写者赢"；删除用墓碑记录 |
| 大内容 | 图片、文件按需拉取（先同步元数据和缩略图） |
| 策略 | 可以选择同步的类型、大小上限，排除敏感内容和特定应用；支持"实时推送"或"只在点击时拉取" |
| 静态加密 | 可选，M3 之后评估（SQLCipher，或者对字段加密） |

**默认只开启局域网同步，不连接任何外部服务器。** 跨网络同步需要用户主动开启。

### 5.6 扩展性（分阶段推进）

1. **M1**：内部 `Action` / `Transformer` trait 和管线，内置动作都通过它实现，相当于"先吃自己的狗粮"。
2. **M2**：CLI（`mypaste search/copy/paste-next/push`）+ 本地 IPC（命名管道，JSON-RPC），方便 AutoHotkey、启动器、脚本集成。
3. **v2**：Extism WASM 插件，可以注册 Transformer、Action 和内容识别器。插件运行在沙箱里，网络、文件等能力必须显式授权。
4. **以后**：MCP Server（把剪贴板作为 AI 的上下文，用户控制共享哪些内容）。

## 6. 移动端规划（M4）

GPUI 不支持移动端，所以采用 **"Rust 核心 + UniFFI + 原生 UI"** 方案。存储、搜索、同步协议全部复用桌面端的代码。iroh 官方也提供了 Swift / Kotlin 绑定。

| 平台 | 形态 | 能力 |
|---|---|---|
| **Android（先做）** | App + **输入法（IME）** + 分享入口 + 通知栏快捷操作 | 作为输入法时可以合法地自动采集，并直接粘贴历史内容；作为普通 App 时，打开时采集、手动推送到电脑 |
| **iOS（后做）** | App + **键盘扩展** + **分享扩展** | 打开 App 时读取剪贴板（系统会弹授权）；用键盘扩展粘贴同步过来的历史；用分享扩展把内容推送到电脑 |

UI 技术待定：Android 用 Jetpack Compose，iOS 用 SwiftUI，这是最自然的选择。如果想少写一份 UI，也可以评估 Compose Multiplatform。到 M4 再决定。

## 7. 路线图

> 不写具体工期，每个阶段以"退出条件"为准。

### M0：技术验证（Spike）—— 先把最大的风险排除掉

每一项都是一个独立的小 demo，**有任何一项不达标，就重新评估技术路线**：

- [ ] GPUI（gpui-kit）在 Windows 上的**中文输入法**输入、候选框位置、高 DPI、多显示器表现
- [ ] 隐藏窗口的常驻内存；热键 → 窗口可见的延迟（目标 < 40MB / < 50ms）
- [ ] 远程桌面、虚拟机下 D3D11 能否正常运行
- [ ] 采集全部格式（文本、HTML、RTF、PNG/DIB、文件）+ 隐私标记检测
- [ ] 焦点还原 + `SendInput` 粘贴，在 Chrome、VS Code、Office、微信、终端、管理员权限窗口里的成功率
- [ ] 托盘（gpui-tray 和 tray-icon 二选一）+ 全局热键 + Mica 背景
- [ ] SQLite FTS5 trigram 在 10 万条中英文混合数据上的搜索耗时

**退出条件**：形成一份 M0 报告，所有指标都有实测数据，技术路线最终确定。

### M1：Windows 本地 MVP

- 采集 → 去重 → 入库 → 列表 → 搜索 → 粘贴，完整闭环
- 键盘流基础操作（5.1 节表格中除动作菜单以外的部分）
- 置顶、收藏、删除；隐私规则；暂停记录
- 托盘、开机自启、设置页（热键、清理策略、主题）
- 安装包（MSI 或 NSIS）+ 便携版；GitHub Actions CI

**退出条件**：自己每天都在用，连续一周没有出现丢数据或粘贴错窗口的问题，并且达到第 2 节的各项指标。

### M2：体验打磨 + 键盘流完整版

- 粘贴队列、动作菜单（`Ctrl+K`）、前缀过滤语法、快速编号粘贴
- 片段和模板（带变量，比如 `{date}`、`{clipboard}`）
- 标签、备注；拼音搜索（评估后决定）
- 数据导入导出；自动更新（候选方案：Velopack）
- CLI + 本地 IPC
- **首个公开版本（v0.1）**，开始收集用户反馈

### M3：多设备同步（桌面 ↔ 桌面）

- 设备配对、受信任设备管理
- 操作日志同步、按需拉取图片和文件
- 同步策略设置；可选的自建中继说明文档
- 先实现"Windows ↔ Windows"，验证协议

### M4：移动端

- 搭建 `mypaste-ffi`（UniFFI）
- Android：App + IME + 同步
- iOS：App + 键盘扩展 + 分享扩展 + 同步

### M5：更多桌面平台 + 插件

- macOS（轮询 changeCount、NSPanel、辅助功能权限）
- Linux（先做 X11 / KDE / wlroots；GNOME Wayland 视情况而定）
- Extism 插件系统 v1；MCP Server

## 8. 工程规范

- **Rust**：stable 版本，用 `rust-toolchain.toml` 锁定；启用 `clippy -D warnings` 和 `rustfmt`；测试用 `cargo-nextest`。
- **依赖锁定**：gpui-kit 和 gpui-pre 精确锁定版本，每次升级都单独提交一个 PR 并做回归测试。
- **测试**：
  - core 层单元测试覆盖采集管线、去重、搜索、操作日志合并。
  - 平台层集成测试在 Windows CI runner 上运行（真实剪贴板）。
  - 同步层用属性测试（多设备随机操作后，各设备结果必须一致）。
- **基准测试**：用 `criterion` 跑搜索和入库；CI 中记录内存和启动耗时，防止性能退化。
- **提交规范**：Conventional Commits；用 release-please 或 cargo-dist 生成变更日志。
- **开源协议（建议）**：**MIT OR Apache-2.0 双协议**（Rust 社区惯例，和 gpui-kit 的 Apache-2.0 兼容，对贡献者和下游都友好）。如果希望防止闭源二次分发，可以改用 GPL-3.0，需要你来定。
- **代码签名**：在 M2 公开发布前解决，候选方案是 SignPath 开源免费签名（待确认申请条件），以减少杀毒软件误报。
